#2026-10-15 재료는 노션 포트폴리오 하나로 둔다

  • 무엇을 정했나: 영상·사이트·게임에 들어가는 경력·프로젝트 내용을 모두 노션 포트폴리오 원문에서 가져온다. 요약본을 따로 만들어 넘기지 않는다.
  • 후보: 노션 내용을 다시 요약해 넘기는 안.
  • 고른 이유: 다시 요약하면 빠지는 내용이 생긴다. 결과물이 영상·사이트·게임으로 여럿이라 같은 원본에서 나와야 숫자가 서로 안 어긋난다.
  • 누가 정했나: 이승준
  • 버린 시도: 요약본 전달.
  • 결과: 프로젝트 상세는 data/quests-detail.json에 노션 본문 블록 그대로 들어 있다. 글 쓸 때 사이트·게임·상세 데이터의 숫자가 같은 표현인지 다시 대조했다.
  • 근거: 개발 글 "목표" 절과 목표 표(dev-post/01-resume-game/tables/tables.html)

#2026-10-15 카드 영상에서 직접 플레이하는 게임까지 방향을 바꾼다

  • 무엇을 정했나: 최종 결과물을 "직접 플레이하는 픽셀 게임이 들어간 포트폴리오 사이트"로 한다.
  • 후보와 순서:
    1. 카드가 넘어가는 40초 소개 영상
    2. 맥북 터미널에 명령어를 치면 이력이 찍히는 영상(52초)
    3. 경력을 스테이지로 바꾼 레트로 픽셀 게임 영상(67초)
    4. 직접 플레이하는 게임
  • 고른 이유:
    • 1 → 2: 템플릿으로 찍은 회사 소개 영상 같았다.
    • 2 → 3: 개발자가 아닌 사람에게는 까만 화면일 수 있다. 기준은 "개발자가 아니어도 재밌나".
    • 3 → 4: 게임처럼 생겼으면 직접 해 볼 수 있어야 재밌다. 영상은 보는 사람이 가만히 있어야 한다. 기준은 "직접 해 볼 수 있나".
  • 누가 정했나: 이승준
  • 버린 시도: 카드 영상, 터미널 영상(사이트에는 넣지 않았다). 픽셀 게임 영상은 사이트 첫 화면 소개 영상(assets/pixel-quest.mp4, 1:07)으로 남았다.
  • 근거: 개발 글 "아이디어" 절

#2026-10-15 QUEST LOG를 카드 목록에서 RPG 퀘스트 저널로 바꾼다

  • 무엇을 정했나: 프로젝트 보는 화면을 왼쪽 목록·오른쪽 상세로 나뉜 퀘스트 저널로 바꾸고, 상세에 노션 본문을 "의뢰 내용 → 보상 → 퀘스트 기록" 순서로 넣는다. 픽셀 폰트는 제목에만 쓴다.
  • 후보: 한 줄 요약만 있는 카드 목록(처음 만든 형태).
  • 고른 이유: 카드 목록은 게임 컨셉과 안 맞았고, 긴 설명을 픽셀 폰트로 읽기 힘들었다. 카드에는 한 줄 요약만 있어서 무엇을 어떻게 풀었는지는 노션에만 있었다.
  • 누가 정했나: 이승준
  • 버린 시도: 카드 목록.
  • 같이 한 일: 스크롤할 때 끊김을 재 보니 레이아웃 계산이 1,087번 일어났고, 216번으로 줄였다(개발 글 수치). 지금 코드는 월드맵 위치를 미리 재 두고 rAF에서 쓰기만 한다(main.js 주석).
  • 근거: 개발 글 "검증 2"

#2026-10-15 폰에서 직접 해 보고 점프와 대사창을 고친다

  • 무엇을 정했나: 자동 입력으로 엔딩까지 가는 것만 확인하지 않고, 배포한 뒤 실제 폰으로 해 본다. 그 결과 점프 최고 높이를 43px(타일 2.7칸)에서 73px(4.6칸)로 올리고, 표지판 대사창을 점수판 바로 아래로 옮긴다.
  • 후보: 자동 테스트만으로 끝내는 안.
  • 고른 이유: 손맛·터치 반응은 실제 폰에서 해 봐야 보인다. 해 보자마자 땅에서 3칸 위 발판에 점프가 닿지 않았고, 대사창이 캐릭터를 가렸다.
  • 누가 정했나: 이승준
  • 버린 시도: 없음.
  • 확인: 모든 스테이지 발판·아이템이 닿는지 계산으로 검사하고, 대표 발판 8곳은 게임에서 직접 점프해 착지를 확인했다. 지금 코드의 점프 초속 -7.0, 중력 0.32(game.js updatePlay)이면 약 73px이 나온다.
  • 근거: 개발 글 "검증 3"

#2026-10-15 영상·음악은 Worker가 Range 응답을 만든다

  • 무엇을 정했나: 영상·음악 요청(/assets/*.mp4, /assets/*.m4a)만 작은 Worker(worker.js → dist/_worker.js)가 받아 요청한 구간만 잘라 206으로 보낸다. 나머지는 정적 파일로 바로 나간다.
  • 후보: 기록 없음.
  • 고른 이유: PC에서는 나오던 영상이 아이폰에서만 안 나왔다. iOS Safari는 영상을 Range 요청으로 받는데 Cloudflare 정적 파일 응답이 Range를 처리하지 않았다.
  • 누가 정했나: 이승준
  • 버린 시도: 없음.
  • 세부: 파일 전체를 메모리에 올리지 않고 스트림에서 구간만 잘라 낸다. Worker 응답에는 _headers가 안 붙어 nosniff·Referrer-Policy를 직접 붙인다.
  • 근거: 개발 글 "아이폰에서만 영상이 안 나왔다", worker.js 주석, README "배포" 절

#2026-10-16 Cloudflare Pages로 옮기고 예전 Workers 주소는 301로 넘긴다

  • 무엇을 정했나: 사이트를 Cloudflare Pages(seungjun-quest.pages.dev)에 ./build.sh && npx wrangler pages deploy로 올린다. 예전 Workers 주소로 들어온 요청은 legacy-redirect/ Worker가 같은 경로의 새 주소로 301 이동시킨다.
  • 후보: 기록 없음.
  • 고른 이유: 기록 없음.
  • 누가 정했나: 이승준
  • 버린 시도: 예전 Workers 주소에서 직접 서비스하던 방식.
  • 근거: fbb62bf의 wrangler.jsonc, build.sh, legacy-redirect/, README "배포" 절. 이전 주소에서 돌던 시기의 커밋은 git에 없다.

#2026-10-16 CSP로 같은 출처 파일만 허용한다

  • 무엇을 정했나: _headers에 default-src 'self', script-src 'self', style-src 'self', frame-ancestors 'none' 등을 건다. 그래서 HTML에 인라인 스크립트·style 속성을 쓰지 않고, 동적 스타일은 JS에서 넣는다.
  • 후보: 기록 없음.
  • 고른 이유: 기록 없음. README에는 "정적 파일 보안 헤더"로만 적혀 있다.
  • 누가 정했나: 이승준
  • 버린 시도: 없음.
  • 근거: fbb62bf의 _headers, main.js 204행 주석("게이지 값은 CSP(style-src 'self') 때문에 style 속성 대신 여기서 넣는다")
