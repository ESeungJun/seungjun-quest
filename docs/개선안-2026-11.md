## 한 줄 정의

채용 담당자·동료 개발자가 링크를 받아 여는 Android 개발자 이력·포트폴리오 한 장짜리 사이트. 경력을 횡스크롤 게임 스테이지로 옮겨 직접 플레이하게 한 것이 차별점이다.

- 핵심 가치: "이력서를 게임으로 만들었다"는 한 문장으로 기억되는 것. 게임 안 적·보스·아이템이 실제 경력 사실(KT 앱 9종, MVP→Compose, 에이전트 4·스킬 7)과 1:1 로 대응한다(`game.js:22-101`).

- 만든 방식: 노션 포트폴리오를 Claude Code 로 옮겼다(`README.md:6`). "AI 티" 진단이 필요한 이유다.

## 구조와 스택

- 빌드 도구 없는 바닐라 JS. `index.html` → `sprites.js`(픽셀 아트 정의·SVG 변환) → `main.js`(페이지 연출·데이터) → `game.js`(캔버스 게임) 순서로 그냥 `<script>` 로 읽는다.
- 프로젝트 요약은 `main.js` 의 `QUESTS`, 상세 본문은 `data/quests-detail.json`(노션 블록 구조: `sections[].blocks[]`, 형식 `p`·`ul`·`quote`·`table`)을 첫 화면에서 `fetch` 한다(`main.js:499`).
- 경력·성과는 `index.html` 에 직접, 같은 내용이 `game.js` 의 `LEVELS` 에 한 번 더 있다.
- 글꼴 Galmuri11 두 굵기(woff2 505KB + 167KB)를 직접 싣는다. 본문용 `Pretendard` 는 이름만 있고 파일이 없다(`styles.css:32`).
- `build.sh` 가 `dist/` 를 만들고 `worker.js` 를 `_worker.js` 로 복사, `_routes.json` 으로 `/assets/*.mp4`·`*.m4a` 만 Worker 를 거치게 한다.
- CSP `default-src 'self'`, 인라인 스크립트·스타일 금지(`_headers:6`). 외부 요청 0건.
- `legacy-redirect/` 는 예전 workers.dev 주소를 301 로 넘기는 별도 Worker.
- 테스트·린트·CI 없음. `?debug` 로 `window.__quest` 만 열린다(`game.js:1183`).

### 🔴 고장

**1. 스크립트가 하나라도 실패하면 사이트 전체가 검은 화면이다**
- 지금 문제: `.boot` 가 `position:fixed; inset:0; z-index:100; background:#000`(`styles.css:91-99`)으로 전체를 덮고, 걷어내는 것은 `main.js:206` 의 `setTimeout` 뿐이다. `main.js` 는 그 전에 `paintSprites()`(`main.js:203`)를 부르므로 `sprites.js` 가 늦거나 막히면 예외로 멈춘다. JS 를 끄고 열어 검은 화면을 확인했다. 스크립트를 안 돌리는 미리보기 봇·읽기 모드도 같다.
- 고치는 방법: 부팅 화면을 CSS 만으로 끝나게 한다. `.boot { animation: boot-out 0.3s steps(3) 1s forwards }` + `@keyframes boot-out { to { opacity:0; visibility:hidden } }`. JS 는 클래스만 덧붙인다. 두 번째 방문부터는 `sessionStorage` 로 건너뛴다.
- 나아지는 점: 스크립트 상태와 상관없이 HTML 에 있는 이름·경력·성과가 보인다.
- 예상 결과: JS 꺼도 STATUS·WORLD MAP·CONTINUE 가 읽힌다. 재방문 때 1초 대기가 없어진다.

**5. 글꼴이 첫 화면 전송량의 62%**
- 지금 문제: `Galmuri11.woff2` 504,736B + `Galmuri11-Bold.woff2` 166,632B 를 전체 글리프 그대로 싣는다(`styles.css:1-12`). `preload` 가 없어 CSS 를 읽은 뒤에야 받기 시작하고, `font-display: swap` 이라 로고 폭이 바뀐다(그래서 `main.js:324` 가 별을 다시 그린다). `_headers` 에 `Cache-Control` 이 없어 글꼴·JS 가 방문마다 재검증된다.
- 고치는 방법: 실제 쓰는 글자(영문·숫자·기호 + 화면에 Galmuri 로 찍히는 한글)만 남겨 서브셋 한다(`pyftsubset --text-file`). 본문 한글은 어차피 시스템 산세리프로 가는 구조이므로 Galmuri 한글은 제목·라벨 분량만 필요하다. `<link rel="preload" as="font" crossorigin>` 추가, `_headers` 에 `/assets/fonts/*  Cache-Control: public, max-age=31536000, immutable`.
- 나아지는 점: 첫 글자가 빨리 뜨고 로고가 흔들리지 않는다.
- 예상 결과: 글꼴 671KB → 100KB 안쪽(서브셋 후 실측 필요), 첫 화면 전송량 1,078KB → 약 500KB.

**6. 폰에서 게임 화면이 흐리고 작다**
- 지금 문제: `fit()` 은 배율이 2 이상일 때만 정수로 내린다(`game.js:1098-1099`). 폰 세로는 1.17배, 가로는 1.7배라 320×192 픽셀이 고르지 않게 늘어나고 11px 글자가 뭉갠다. 세로에서는 844px 화면 중 224px 만 게임이다.
- 고치는 방법: 캔버스 뒤판을 기기 픽셀 기준 정수배로 잡는다. `k = floor(min(availW, availH 기준 배율) × devicePixelRatio)`, `canvas.width = 320×k`, CSS 크기는 `320×k / dpr`, `ctx.setTransform(k,0,0,k,0,0)`. 세로 폰은 패드를 캔버스 아래로 붙여 남는 높이를 줄인다.
- 나아지는 점: 폰에서도 픽셀이 칼같이 떨어진다.
- 예상 결과: dpr 3 폰 기준 세로는 게임 1픽셀 = 기기 3픽셀(화면 320×192, 지금보다 조금 작지만 선명), 가로는 기기 5픽셀(화면 533×320). 세로에서 크게 보려면 가로 회전 안내를 지금처럼 유지한다.

- 고치는 방법: `data/profile.json`(경력·성과·기술·연락처)을 하나 두고 `index.html` 은 `build.sh` 에서 채워 넣거나, 최소한 `main.js`·`game.js` 가 같은 전역 상수(`window.PROFILE`, `sprites.js` 처럼 먼저 읽는 파일)를 쓴다.
- 나아지는 점: 수치를 고칠 때 한 곳만 고친다.
- 예상 결과: 사실 정의 3곳 → 1곳.

**10. 영상 Range Worker 가 요청마다 파일을 처음부터 흘린다**
- 지금 문제: `sliceStream`(`worker.js:25-38`)은 원본을 0바이트부터 읽으며 버린다. 뒤쪽을 찾는 요청은 11MB 가까이 Worker 를 통과한다. 크기를 모르면 한 번 끝까지 세고(`worker.js:43-54`) Worker 인스턴스마다 다시 센다. 영상 재생은 Range 요청을 여러 번 보내고, 그때마다 Functions 호출 1건이다.
- 고치는 방법: (가) 지금 Pages 정적 응답이 Range 를 처리하는지 `curl -r 0-99 -I` 로 다시 확인하고, 되면 Worker 를 뺀다. (나) 안 되면 `build.sh` 가 파일 크기를 `dist/_sizes.json` 으로 적어 Worker 가 세지 않게 한다. (다) 영상 자체를 줄인다. 픽셀 아트라 960×540·CRF 26 정도로 다시 인코딩해도 화면이 같다.
- 나아지는 점: 재생 시작이 빨라지고 무료 호출 한도를 덜 쓴다.
- 예상 결과: (다)만 해도 11.1MB → 3MB 안팎(실측 필요).

**11. 문서가 실제와 다르다**
- 지금 문제: `README.md:58` 은 `docs/` 에 기획서·설계서·구현도·결정기록이 있다고 적었지만 `docs/media/` 만 있다. `_headers:1` 주석은 "Cloudflare Workers 정적 파일"인데 배포는 Pages 다.
- 고치는 방법: README 표에서 그 줄을 지우고 `_headers` 주석을 Pages 로 고친다.
- 나아지는 점: 저장소를 보러 온 면접관이 없는 폴더를 찾지 않는다.
- 예상 결과: 문서와 트리 일치.

**12. 접근성: 역할과 실제 동작이 어긋난다**
- 지금 문제: 탭은 `role="tablist"` 인데 화살표 키 이동이 없고 6개가 모두 같은 `aria-controls` 를 가리킨다(`index.html:205-212`). 인벤토리 칸은 `<li tabindex="0">` 에 역할이 없고 설명 칸이 `aria-live` 가 아니다(`main.js:514-529`, `index.html:227`). HUD 버튼은 폰에서 75×28, 69×30px 로 손가락 기준 44px 에 못 미친다(실측). 전역 커스텀 커서(`styles.css:34·54·63`)가 링크 위에서도 화살표라 누를 수 있다는 신호가 없다.
- 고치는 방법: 탭은 `aria-pressed` 필터 버튼으로 낮추거나 화살표 키를 구현한다. 칸은 `<button aria-describedby="slot-desc">`, 설명 칸 `aria-live="polite"`. HUD 버튼 `min-height:44px`. 링크·버튼 위에서는 손가락 모양 픽셀 커서를 따로 준다.
- 나아지는 점: 키보드·화면 읽기·터치 사용자가 같은 내용을 얻는다.
- 예상 결과: 44px 미만 터치 대상 4개 → 0개.

### ⚪ 사소

- `--font-body` 첫 값 `Pretendard` 는 파일이 없어 항상 대체 글꼴로 간다(`styles.css:32`). 이름을 지우거나 서브셋을 싣는다.
- 번호 체계가 셋이다. 섹션 머리 "STAGE 01~05"(`index.html:88` 등), HUD "WORLD 1-0/1-1/2-2/3-1/3-1/END"(`data-world`), 게임 스테이지 1-1~3-1. QUEST LOG 와 INVENTORY 가 같은 3-1 이다(`index.html:198·222`).
- `.continue-title` 이 `div` 라 연락 섹션에 제목 요소가 없다(`index.html:234`).
- 게임 엔딩의 메일·GitHub 는 캔버스 글자라 누르거나 복사할 수 없다(`game.js:1053·1060`).
- `min-height:100vh`(`styles.css:182`)는 모바일 주소창에서 출렁인다. `100dvh` 로.
- 화면 아무 데나 누르면 "+10" 과 파티클이 난다(`main.js:194-200`). 링크를 누를 때도 난다.
- 터치 기기에는 일시정지 버튼이 없다(P 키뿐, `game.js:207`).

**1. 빠른 이력 보기 (게임 안 하는 사람의 경로)** · 크기 M

**2. 프로젝트별 주소와 정리된 항목** · 크기 M

### 바꿀 방향

**타이포 척도.** Galmuri11 은 12px 배수에서만 쓴다.

| 역할 | 크기 | 쓰는 곳 |
|---|---|---|
| 로고 | 96px(폰 48px) | SEUNGJUN QUEST, CONTINUE? |
| 섹션 제목 | 48px(폰 36px) | STATUS 등 |
| 카드 제목 | 24px | 회사명, 퀘스트 제목, 창 머리 |
| 라벨 | 12px, 자간 1px | HUD 라벨, 등급, 기간, 키워드 |
| HUD 값·버튼 | 24px(폰 12px 굵게) | 점수, PLAY |

**색 역할.** 스프라이트 팔레트(`sprites.js:2-6` 의 13색)는 그대로 두고, UI 가 쓰는 색을 역할로 묶는다.

**격자와 여백 리듬.** 지금 섹션 위 여백이 전부 120px, 창 안쪽이 26/30px, 간격이 40·70·28·24·14px 로 제각각이다(`styles.css:335·361·384·447·537·602·741`). 픽셀 단위 `--px:4px`(`styles.css:29`, 정의만 하고 쓰지 않는다)의 배수로 정한다: 8 · 16 · 24 · 48 · 96. 섹션 사이 96, 제목과 내용 사이 48, 창 안쪽 24, 칸 사이 16, 글줄 사이 8. 본문 폭은 12칸 격자(1160px, 칸 사이 24)로 두고 STATUS 는 7:5, QUEST 는 4:8 로 맞춘다.

**섹션마다 다른 그릇.**

- WORLD MAP: 지금 구성 유지. 창 테두리만 안쪽 선(`#3a4466`)으로 낮추고 깃발을 주인공으로.
- IMPACT: 카드 없이 점수판처럼 큰 숫자 4개를 가로로. 숫자 48px 초록, 라벨 12px.

- INVENTORY: 칸 격자 유지, 아이콘은 16×16 스프라이트로.

영문 게임 용어만으로는 QUEST LOG 가 프로젝트 목록이라는 것을 한 번 해석해야 한다. 한글 뜻을 붙이면 컨셉과 정보가 같이 간다. "STAGE 0N" 번호는 HUD 의 WORLD 표기와 겹치므로 뺀다.

**모션 원칙.**
1. 전환은 전부 `steps()`. 튀는 `cubic-bezier` 두 곳을 `steps(4)` 로.
2. 무한 반복은 스프라이트(캐릭터 걷기·대기, 별)에만. 버튼(`.tv-play span` 의 `idle`, `styles.css:299`)과 문구(`.scroll-hint`)는 멈춘다.
3. 점수·파티클은 "게임 행동"에만: 블록 치기, 경력 지점 통과, 퀘스트 열기. 아무 데나 눌렀을 때의 +10 은 뺀다.
4. 게이지처럼 `width` 를 바꾸는 전환은 `transform: scaleX` 로(탐지기 지적 6건).
5. 주사선은 타이틀·TV·게임에만. 본문 위에서는 끈다.

**아이콘.** `sprites.js` 에 PAD(게임패드)·MAIL·STAR·NOTE(음표)·CLOSE 를 8×8 로 추가해 이모지와 `✉ ★ ♪ ✕ ↻` 를 바꾼다. 인벤토리 12칸도 16×16 스프라이트로(Kotlin 은 K 방패, Compose 는 겹친 마름모처럼 단순한 형태). 스프라이트는 한 글자 = 한 픽셀 문자열이라 추가 비용이 줄당 수십 바이트다.

## 확인 못 한 것

- 배포된 사이트(`pages.dev`)는 열지 않았다. 외부 요청에 프로젝트 이름이 들어가기 때문이다. 그래서 실제 응답 헤더, Pages 정적 응답의 Range 지원 여부, 없는 경로가 `index.html` 을 200 으로 돌려주는지(404 페이지 없음)는 확인하지 못했다.
- Galmuri11 의 권장 크기가 12px 배수라는 점은 글꼴 배포 문서로 확인하지 못했다(`fontTools` 없음). 캡처상 15px 에서 획이 고르지 않은 것은 확인했다.
- 실제 Chrome 에서는 창 크기가 바뀌지 않아 데스크톱 폭과 390px 폭을 직접 보지 못했다(606px 만 확인).
- 실제 iOS Safari·안드로이드 Chrome 기기 확인 없음. 터치 패드 조작감, iOS 영상 재생, 가로 회전은 헤드리스 에뮬레이션으로만 봤다.
- 게임 5스테이지를 끝까지 깨 보지는 않았다. 코드로 읽은 범위에서 진행이 막히는 곳은 찾지 못했다.
- Lighthouse 점수·LCP 실측 없음(로컬 서버라 의미가 작다).
- 서브셋·재인코딩 뒤 크기는 추정이다.
- 사용자에게 물을 것: (1) 타이틀 영상을 게임 자동 데모로 바꿔도 되는지, (2) n8n 자동화의 시간 절감 수치가 있는지, (3) 프로젝트별 기간·역할·팀 규모를 공개해도 되는 범위, (4) LinkedIn·이력서 PDF 를 걸지, (5) 영문판이 필요한지.
